# orbital-web-jw

Marketing site for the Orbital product launches: **CACHE** (verified binary
storage, target August 2026), **BUILD** (typed build system, target September
2026), the shared pricing page, and the verification path. The **Orbital
Confirm** runner follows later in 2026; leave room for it.

Read `02-Sales-Page-Handoff.md` before copy or design work. Its decisions and
style rules are binding. Unresolved launch work is tracked in
`docs/launch-blockers.md`.

## Stack

This is a typed PureScript/Halogen static site generated by Hydrogen and built
with Buck2 inside a pinned Nix environment.

- Page structure: `src/Orbital/Pages/*.purs`
- Shared layout: `src/Orbital/Layout.purs`
- Routes and metadata: `src/Orbital/Route.purs`
- Static generator: `src/Orbital/SSG.purs`
- Page-specific styles: `styles/pages/*.css`
- Vendored design system: `halogen-orbital/`
- Browser integrations: `scripts/`, `waitlist.js`, and the vendored runtime

Do not fork vendored design tokens. The browser scripts are deliberately small
interop assets; page structure and route metadata belong in PureScript. There
is no npm build.

The page skeleton uses local fonts, `orbital.css`, `body class="grain"
data-ambient`, the shared `.bar` navigation, `.wrap` main content, `.foot`, and
the Orbital runtime and theme scripts. Marketing components include `.phero`,
`.clone`, `.sh`, `.feat`, `.glass`, `.statband`, `.ctaband`, and `.term`.
Motion hooks include `data-reveal`, `data-reveal-stagger`, and
`data-split="char"`. Never gate content visibility on JavaScript alone.

## Binding product and copy rules

1. Keep a separate page per product, one shared pricing page, and one
   subscription. Tiers gate account-level throughput, retention, and SLAs, not
   product access. Seats are free. SSO and audit logs are available at every
   tier.
2. Preserve the developer path and the compliance or safety-critical buyer
   path.
3. Pricing is placeholder-only until the team resolves it. On-premises and
   air-gapped claims are pending. Never publish an unmeasured number. Label each
   quantitative claim measured, target, or estimate and link its basis.
4. Use lay-readable copy with no em dashes and no unexplained jargon. Bold an
   Orbital product name on first use. Do not mention WARRANT or crypto
   positioning. Do not use Straylight, sensenet, or weyl in site copy.

## Waitlist contract

Until general availability, the primary CTA is "Get early access". Forms on the
overview, CACHE, and BUILD pages post to Supabase project `orbital-site`
(`lhmodcikykyoxpaojeyn`, organization `jwpr`). The publishable key in
`waitlist.js` is public by design.

The `waitlist_signups` table has row-level security enabled, no policies, and
all direct grants revoked. The browser can call only `join_waitlist`,
`waitlist_count`, and `referral_count`. Emails are not readable with the shipped
key. Service-role credentials are required for exports and must never enter the
repository.

The confirmation page preserves queue position, referral attribution, reward
progress, share text, and share links. Signups preserve first-touch UTM values
and external referrer. Common disposable-email domains are rejected. Counters
show only after the real count reaches the configured threshold and are never
seeded.

At launch, replace the waitlist CTAs with account signup CTAs and resolve every
item in `docs/launch-blockers.md`.

```console
nix flake check --accept-flake-config

```

Deployment uses the flake's prebuilt Vercel app only after the correct project
has been linked. Do not relink or promote a production project as part of an
ordinary build or content change.
