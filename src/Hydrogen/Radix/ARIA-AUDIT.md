# STR-337 Interactive Port — ARIA/Role/Data Audit Punch-List

16 primitives audited. **58 blocking divergences** across 14 primitives (Tabs and Toggle are clean). Fixes below are ranked blocking-first, grouped by the cross-cutting pattern they belong to so STR-338 can knock out whole families at once.

---

## CROSS-CUTTING (fix these patterns once, apply everywhere)

### X1. `aria-controls` / content `id` linkage is dropped across the entire disclosure family — BLOCKING
Every trigger→content disclosure omits BOTH halves of the relationship: the trigger never emits `aria-controls={open ? contentId : undefined}` and the content never emits `id={contentId}`. Add a generated `contentId`, stamp `id` on content, and gate `aria-controls` on open.
- **Affected:** Dialog, AlertDialog, Popover, DropdownMenu, Select, Accordion, Collapsible (Collapsible & Accordion emit `aria-controls` UNCONDITIONALLY — must gate on open; the rest omit it entirely).

### X2. `aria-modal="true"` / `="false"` added where upstream NEVER sets it — BLOCKING
Radix Dialog deliberately omits `aria-modal` and aria-hides siblings via `hideOthers` (explicit comment dialog.tsx:274). Remove `aria-modal` from content entirely; non-modal case emitting `aria-modal="false"` is also semantically wrong.
- **Affected:** Dialog, AlertDialog.

### X3. Trigger `data-state` is missing on disclosure triggers — BLOCKING
Upstream stamps `data-state=open|closed` on the trigger BUTTON; the port stamps it only on content (or not at all). Add `data-state` to the trigger.
- **Affected:** Dialog, AlertDialog, Popover. (Tooltip emits the wrong value — see X4.)

### X4. `data-state` value vocabulary is wrong/static across Popper-content primitives — BLOCKING (Tooltip), minor elsewhere
- **Tooltip (blocking):** port emits `open|closed`; upstream emits the tristate `closed|delayed-open|instant-open`. `"open"` is a value upstream never produces, on both trigger and content. Map to the tristate.
- **Popover (blocking):** content hardcodes `"open"`; upstream derives `getState(open)` and emits `closed` during exit. Drive from open state.
- **Minor pattern (hardcoded `"open"`, only correct because conditionally mounted; surfaces under exit-animation):** AlertDialog content/overlay, DropdownMenu content, ContextMenu content, Select content, HoverCard content, Accordion. Acceptable for v1 (no Presence) but flag for the Presence pass.

### X5. Menu item ARIA state attributes missing — BLOCKING
Menu items omit `aria-disabled` (present-when-disabled) and `data-highlighted=""` (present on the focused/roving item). The port tracks roving focus for tabindex but never surfaces `data-highlighted`. Emit both.
- **Affected:** DropdownMenu, ContextMenu, Select (Select item also missing `aria-labelledby` + wrong `aria-selected` condition).

### X6. Menu content `aria-orientation="vertical"` missing — BLOCKING
`MenuContentImpl` always sets `aria-orientation="vertical"` on the `role=menu` element. Add it.
- **Affected:** DropdownMenu, ContextMenu.

### X7. Orientation attributes emitted unconditionally where upstream leaves them undefined-by-default — BLOCKING
RovingFocusGroup only stamps `aria-orientation`/`data-orientation` when the consumer passes `orientation`; default is ABSENT. The port hardcodes `"vertical"`. Make orientation attrs conditional on an explicit orientation prop (or drop them by default).
- **Affected:** RadioGroup (root `aria-orientation`, root + item `data-orientation`), ToggleGroup (root `aria-orientation` — upstream never sets it on root at all), Accordion (root `aria-orientation` — extra, root has no role).

### X8. Trigger element/role mismatch — BLOCKING
The port renders the wrong host element so the implicit/explicit role is wrong.
- **Checkbox:** `<button>` with no `role` → exposes `role=button`; add explicit `role="checkbox"` (module doc already claims it).
- **HoverCard:** port renders `<button>`; upstream is `<a>` (Primitive.a). Render an anchor.
- **Select:** trigger omits `role="combobox"` and instead adds `aria-haspopup="listbox"` (upstream sets neither/the latter never). Add `role="combobox"`, drop `aria-haspopup`.
- **ToggleGroup:** root hardcodes `role="group"`; must be `radiogroup` (single) / `toolbar` (multiple).

### X9. `hidden` attribute missing on collapsible content — BLOCKING
Upstream sets `hidden={!open}` on content (present while closed/closing). Port omits it.
- **Affected:** Collapsible (missing entirely). Accordion already handles it correctly (closed branch).

### X10. Form bubble-input subtree absent — minor→blocking under full-subtree oracle
The hidden `<input aria-hidden tabindex=-1>` for form participation is dropped (documented v1 deferral). A full-subtree a11y oracle sees `button` vs `button+input`.
- **Affected:** Switch (flagged blocking on the aria-hidden node), Checkbox, RadioGroup. Defer to the forms pass but track.

## PER-PRIMITIVE BLOCKING FIXES (ranked)

### Select (10) — worst offender
1. Trigger: add `role="combobox"`.
2. Trigger: remove `aria-haspopup="listbox"` (upstream never sets it).
3. Trigger: add `aria-controls={open ? contentId : undefined}`.
4. Content: add `id={contentId}` (listbox; the aria-controls target).
5. Content: remove `data-side` from the listbox (only on PopperContent in `position=popper`; default is item-aligned).
6. Content: remove `data-align` from the listbox (same).
7. Item: add `aria-labelledby={textId}` (needs an ItemText id).
8. Item: fix `aria-selected` condition to `isSelected && isFocused` (VoiceOver-stutter fix).
9. Item: add `data-highlighted=""` present-when-focused.
10. Item: add `aria-disabled` present-when-disabled.

### DropdownMenu (7)
1. Trigger: add `id={triggerId}`.
2. Trigger: add `aria-controls={open ? contentId : undefined}`.
3. Content: add `id={contentId}`.
4. Content: add `aria-orientation="vertical"`.
5. Content: add `aria-labelledby={triggerId}`.
6. Item: add `aria-disabled` present-when-disabled.
7. Item: add `data-highlighted=""` on the focused item.

### Dialog (6)
1. Trigger: add `data-state=open|closed`.
2. Trigger: add `aria-controls={open ? contentId : undefined}`.
3. Content: add `id={contentId}`.
4. Content: emit `aria-labelledby={titleId}` UNCONDITIONALLY (and always set the title `id`).
5. Content: emit `aria-describedby={descriptionId}` UNCONDITIONALLY (and always set the description `id`).
6. Content: remove `aria-modal` (X2).

### Tooltip (6)
1. Split anatomy: add the VisuallyHidden `role="tooltip"` + `id={contentId}` sibling node (carrying `ariaLabel || children`); remove role/id from the visible content div.
2. Content `role="tooltip"`: move off the visible div onto the VH node (per #1).
3. Content `id={contentId}`: move onto the VH node (per #1).
4. Trigger: make `aria-describedby` conditional on open (currently unconditional → dangling ref when closed).
5. Trigger `data-state`: emit tristate `closed|delayed-open|instant-open` (not `open|closed`).
6. Content `data-state`: emit the tristate (not hardcoded `"open"`).

### Popover (5)
1. Content: add `role="dialog"`.
2. Content: add `id={contentId}`.
3. Trigger: add `aria-controls={open ? contentId : undefined}`.
4. Trigger: add `data-state=open|closed`.
5. Content: derive `data-state` from open state (not hardcoded `"open"`).

### ToggleGroup (5)
1. Root: `role` must be `radiogroup` (single) / `toolbar` (multiple), not hardcoded `group`.
2. Root: remove `aria-orientation` (upstream root never sets it).
3. Item (single mode): add `role="radio"`.
4. Item (single mode): add `aria-checked={pressed}`.
5. Item (single mode): suppress `aria-pressed` (upstream sets it `undefined`); keep only in multiple mode.

### AlertDialog (4)
1. Trigger: add `aria-controls={open ? contentId : undefined}`.
2. Trigger: add `data-state=open|closed`.
3. Content: add `id={contentId}`.
4. Content: remove `aria-modal="true"` (X2).

### ContextMenu (4)
1. Content: add `aria-orientation="vertical"`.
2. Content: add `data-radix-menu-content=""` (load-bearing — content onKeyDown uses `closest('[data-radix-menu-content]')`).
3. Item: add `aria-disabled` present-when-disabled.
4. Item: add `data-highlighted=""` on the focused item.

### RadioGroup (3)
1. Root: make `aria-orientation` conditional on explicit orientation prop (X7).
2. Root: make `data-orientation` conditional (X7).
3. Item: make `data-orientation` conditional (X7).

### Accordion (3)
1. Root: remove `aria-orientation` (root has no role; upstream sets only `data-orientation`).
2. Trigger: gate `aria-controls` on open (currently unconditional; closed trigger must have none).
3. Trigger: add `aria-disabled=true` when an open item is non-collapsible (single + `!collapsible`).

### Collapsible (2)
1. Trigger: gate `aria-controls` on open (currently unconditional).
2. Content: add `hidden` attribute when `!open` (present-while-closed/closing).

### HoverCard (1)
1. Trigger: render `<a>` (Primitive.a) instead of `<button>` to match upstream's anchor/implicit-role.

### Checkbox (1)
1. Trigger: add explicit `role="checkbox"` to the button (doc claims it; render omits it).

### Switch (1)
1. Restore the `SwitchBubbleInput` (`<input type=checkbox aria-hidden tabindex=-1>`) — full-subtree oracle sees the missing node (X10; forms-pass candidate).

### Tabs (0) — clean
No blocking divergences. Minor: root `dir` not emitted; id token uses `-panel-` vs upstream `-content-` (self-consistent, only a literal-id oracle cares); trigger has an extra harmless `data-orientation`.

### Toggle (0) — clean
Single-part primitive, all three attrs (`aria-pressed`, `data-state`, `data-disabled`) faithful.

## NOTABLE MINORS worth folding into the same passes
- **`data-disabled` on indicator/thumb/header sub-parts:** Checkbox indicator, Switch thumb, Accordion header, RadioGroup indicator all omit `data-disabled` present-when-disabled (styling-hook; cheap to add).
- **`data-side`/`data-align` provenance:** DropdownMenu/ContextMenu emit these on the content node directly — verify the port's Popper layer doesn't also emit them (avoid duplication); for Select they are flat-out wrong on the listbox (X-Select #5/#6).
- **`aria-required="false"` case:** RadioGroup omits the attribute when not required; upstream renders `aria-required="false"`.
- **Tristate `data-state` under Presence:** the X4-minor set (hardcoded `"open"`) all become real once exit-animation/Presence lands.
